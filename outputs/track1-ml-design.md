## 1. 模型放在哪里

| 环节 | 方法 | 输出 |
| --- | --- | --- |
| 检索候选文书 | 法条编号/名称规则；语义检索作为补充 | 可核查的候选文书及命中位置 |
| 判断法条角色 | 固定格式抽取；有标注后再尝试小分类器 | 本案指控、引用先例、其他讨论、不明确 |
| 抽取案情与司法理由 | 预训练模型按 schema 抽取，程序验证引句，人工审阅 | 被指控行为、身份/表达关联、程序类型、裁定及理由 |
| Charge–Conduct 对照 | 法律成员确认构成要件；模型检索并整理对应段落 | 要件—控方指控—法院判断—信息缺口矩阵 |
| 跨案统计和评分研究 | 去重、分母定义、分层统计、专家量表和权重敏感性分析 | 法条画像和带样本量的历史证据表 |

第一版推荐把模型资源用于抽取和段落检索。是否自己训练分类器，取决于人工标签数量与质量；即使文书很多，也不等于已有法条危险程度的金标准。

## 2. 先确认数据单位和真实字段

AWS 登记页说明该项目提供来自 eCourts 的高院文书、JSON 和 Parquet 元数据。它是整理后的开放数据项目。

标准 Athena 表列出了 court、title、description、judge、pdf_link、cnr、registration date、decision date、disposal nature 等字段，没有全文字段。描述字段不能直接当判决全文。原项目还说明部分 mobile 数据有更丰富的 case-details 表；实际所选法院的字段和覆盖仍需检查。

要区分：

- 文书：某次 judgment/order，用稳定的文书键保存。
- 高院程序：保释申请、撤销申请等，尽量以 CNR 和程序信息关联。
- 底层刑事案件家族：同一 FIR/指控事件可能产生多个程序与裁定；CNR 不必然能独自完成跨程序连接。

同一法条在先例中出现，不能据此将当前案件计为该法条的追诉。同案多份 order 也不能直接计成多起刑事案件。

检索和抽样协议先固定到“法条 × 法院 × 时期”。识别本案实际指控后，在约定范围内全取或随机抽取；不能只用 quashing、abuse 等关切词挑出文书，再把所得比例称为该法条的通常表现。结果、关切词可用于另外的定向案例研究，但该样本单独报告。

来源：[AWS 登记页](https://registry.opendata.aws/indian-high-court-judgments/)、[元数据 schema](https://github.com/vanga/indian-high-court-judgments/blob/main/opendata/tutorials/ATHENA.md)、[原项目数据说明](https://github.com/vanga/indian-high-court-judgments/blob/main/opendata/docs/dataset.md)。本次核查的是项目文档，尚未检验实际数据行。

## 3. 建议的最小抽取 schema

| 字段组 | 必需信息 |
| --- | --- |
| 来源与版本 | document_id、CNR/案件家族键、法院、裁定日期、来源 URL、文本版本 |
| 法条 | law/section、适用版本、本案指控或仅引用、原文证据 |
| 主体与行为 | 新闻/表达关联、被指控行为、当事人身份；未知明确标记 |
| 程序 | bail / anticipatory bail / quashing / other；具体申请对象 |
| 裁定 | granted / denied / partial / procedural / pending / unclear；裁定针对什么 |
| 理由 | 要件不足、主观要件不足、指控模糊、程序问题、和解、其他、未说明；允许多标签 |
| 事实归属 | 控方指控、申请人主张、法院判断、引用先例、其他来源 |
| 证据锚点 | 原文引句、页码或字符位置、所支持字段 |
| 时间与缺失 | 可获得的 FIR/申请/羁押日期，日期含义；未获知项 |

关键规则：引句出现在原文里只是第一步，还要人工核查它是否支持字段，以及属于谁的陈述。例如申请人提出“abuse of process”，不能自动记成法院认定。

## 4. Charge–Conduct Distance 的可验证版本

建议首先输出“要件匹配情况”，暂时不生成单一距离数字。

| 构成要件 | 本案具体指控 | 法院对此的判断 | 证据状态 |
| --- | --- | --- | --- |
| 经法律成员确认的行为要件 | 原文中控方指控的行为 | 法院处理该要件的原文 | 已讨论/未讨论/不明确 |
| 经确认的主观要件 | 有关意图或知识的指控 | 法院认为是否存在相应问题 | 已讨论/未讨论/不明确 |
| 所需结果或关联 | 指控的损害、妨碍或其他结果 | 法院是否指出缺失或联系不足 | 已讨论/未讨论/不明确 |

可抽取“法院明确指出某要件缺失”作为历史观察指标；材料未提及该要件时保留未知。控方指控、事实成立与法院认定要分别存储。

Claude 最后一轮提醒：明确展示的空洞指控不应全部归为资料缺失。为保留这个信号，分别记录两个维度：

- **指控内容**：有具体事实、仅重复法条措辞、明确可评估但未提供相应事实、材料不足。只有引文覆盖和法律复核支持时，才使用“未提供相应事实”；截取的一小段没有提到，不足以做此判断。
- **法院判断**：明确认为要件满足、明确认为要件不足、未处理该要件、不明确。即使有具体事实指控，法院也可能认为不足，因此这两个维度不能合成一个互斥标签。

每项同时保存原文与覆盖情况。若以后计算要件比例，分母只含明确可评估项，并另报可评估项数/适用要件总数；信息覆盖低时不输出可比较的单一距离分数。

语义向量可以帮助找到段落，不能决定法律要件是否满足。假设报道抗议现场的记者被控妨碍公务：描述中“报道”和“妨碍”语义不同，仍需要核查是否另有具体阻碍行为的指控。

## 5. 法条评分先做两张表

**结构画像表**：法律成员确认条文版本、范围、明确性、主观要件、抗辩保障、刑罚及程序暴露，逐项写评分锚点和依据。

**历史观察表**：展示去重后的样本数、表达关联、申请类型、裁定结果及法院理由，并明确分母和缺失情况。

建议先分开展示，合并分数留作后续试验。只有 8–12 个候选法条时，不宜因为有许多裁定就声称能学出可靠的法条权重。

如果最终采用 0–100 分，它是按已公开量表得到的指数，不是“该法条被滥用的百分比概率”。专家一致性和排序稳定性可以验证可重复性，不能单独证明评分在现实中预测正确。

历史指标的口径：

- 频率：在约定覆盖范围和筛选规则下找到的独立案件/程序数量。
- 撤销结果：相应撤销申请中已有可解释裁定的结果；区分全部、部分和程序性处置。
- 保释结果：相应类型申请的结果；普通保释与预先保释分别统计。
- 多重指控：案件的实际指控集合，不按文书重复次数累加。
- 时长：明确起止日期及其含义。高院注册到裁定的间隔不直接代表全部刑事程序或羁押时长。

每个指标声明用“案件家族”还是“独立申请”作分母。若使用申请，重复申请先关联并报告，跨法条比较同时展示案件数与申请数，检查结果是否由少数多次申请的案件主导。时长保存最后可知状态日期；没有找到后续 order，不能据此推断案件截至今天仍未结。尚未观察到结局的程序报告截至最后证据日期的已观察时长；只统计已完成程序可能低估长时间未完成的程序。

高院公开文书是经过选择的样本，观察到的撤销或保释比例不能直接外推成所有起诉中的滥用率。记者/表达案件与其他案件比较时，尽量按法条、法院、时期、申请类型和行为类别匹配。未完成程序保留未完成状态，不当成失败结果。

## 6. 两个优先实验

**模型实验：可核查字段抽取。**

先从候选目录中选 2–3 条法律、少数法院验证，再扩展到团队计划的 8–12 条。预先冻结一批人工标注测试文书，按案件家族划分。比较法条/关键词规则与固定 schema 的模型抽取，检查：法条角色、程序与裁定分类、理由分类、原文支持率、归属错误、未知项处理。人工复核一部分双标样本，并记录分歧原因。

分类字段可以分别报告 precision/recall/F1，原文支持和归属正确性用人工核查分子/分母。双人标注一致性另报，不与模型表现混用。方法比较使用相同测试材料、输入范围和指标；不能把要件分类的 κ 与语义排序的 Spearman 直接比较来证明某种方法更好。若比较案件级排序，另用同一人工排序参考及同一排序指标。

**评分实验：专家一致性与敏感性。**

请法律成员依据同一材料独立评分，并对法条进行少量成对比较。合理改变候选权重和剔除不同法院/时期样本，观察排序是否稳定；报告对某个假设依赖较强的法条。历史结局用于描述使用模式，不自动成为“法律真实危险程度”的训练标签。

结果只报告实际测量的分子、分母和错误案例。当前两个实验验证抽取与评分依据，后续还需另做仅使用当时材料的早发现回放。
